## Feature 4: Manual Entry Portal Features
### 1. Executive Summary
 * **Title:** High-Friction-Reduction Entry Interface
 * **Summary:** This feature focuses on the user-facing "capture" environment. It provides a specialized workspace designed for speed, data safety, and clarity, ensuring that the act of manual logging is as seamless as possible through auto-save mechanisms and rich-text support.
### 2. Context & Objectives
 * **Background:** Manual entry is the primary bottleneck of a logging system. If the interface is clunky or prone to data loss (e.g., losing a long entry due to a refresh), the user will eventually stop logging.
 * **Goals:** * Ensure zero data loss via robust drafting logic.
   * Provide a "Focus Mode" for long-form entries.
   * Enable rich formatting (Markdown) to make logs readable and structured.
 * **Non-Goals:** This is not a collaborative editor; it is optimized for a single-user, personal workflow.
### 3. Proposed Solution
#### High-Level Architecture
The portal will be a "State-Aware" editor. It utilizes local browser storage (IndexedDB or LocalStorage) to keep a mirror of the current draft before it is officially committed to the file system.
#### Detailed Design
 * **Drafting & Auto-Save:** Every 5 seconds (or upon a pause in typing), the system saves the current content to a "Local Draft" cache. If the app closes unexpectedly, the user is prompted to resume the draft upon re-entry.
 * **Markdown Live-Preview:** A side-by-side or "WYSIWYG" style editor that renders headers, bold text, and code blocks in real-time.
 * **Smart-Paste:** Architecture that detects pasted content (like a URL or an image) and automatically formats it as a Markdown link or triggers the file-attachment workflow.
### 4. Alternatives Considered
 * **Plain-Text Area:** Dismissed. While fast, it lacks the visual hierarchy needed for organizing complex thoughts or instructions.
 * **Direct-to-Disk Saving:** Dismissed as the primary method during typing, as frequent disk I/O can be taxing and doesn't allow for an "Undo" or "Cancel" safety net.
### 5. Execution Plan
 * **Phase 1:** Build the core editor component with Markdown support and basic styling.
 * **Phase 2:** Implement the "Draft Manager" to handle auto-save and recovery.
 * **Phase 3:** Integrate a "Quick-Insert" toolbar for common logging elements (timestamps, category tags, or checklists).
### 6. Risks & Mitigations
 * **Risk:** Conflicting drafts if the user opens the same log on two different devices.
 * **Mitigation:** Implement a "Stale Draft" check that compares the local draft timestamp against the file’s recorded_at metadata on the server/disk.
